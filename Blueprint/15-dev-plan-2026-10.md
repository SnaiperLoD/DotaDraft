## 1. Цель и границы

**Цель.** Закрыть расхождения между тем, что экран говорит игроку, и тем, что считает бой. Поставить на место ограждения, которых сейчас нет (чётность скрытых тегов, граница модулей, ключи локалей). Подготовить игру к закрытому тесту на 3–5 друзей.

**Не входит в этот план:**
- любые изменения коэффициентов, весов, тегов, фаз, `realWinRateWeight`, кап 0.3, `WIN_WEIGHT_BY_TIER`, пороги ярусов;
- влив shadow `r2_f_farm`;
- рефетч и пересчёт на внешних данных (OpenDota и т. п.);
- сама аналитическая сессия по дисперсии винрейтов — для неё отдельный промт и `Blueprint/16-variance-lab.md`.

Причина границы: Calibration Change Rule и Real-Data Recompute Rule (`Blueprint/01-core-rules.md`). Всё, что в этом плане, допустимо «без спроса» по тем же правилам: багфикс, copy/UI без смены математики, тесты на существующее поведение.

**Доказательство, что математика не тронута.** Фаза 0 создаёт golden-снимок исходов `assessBattle`. Он должен оставаться бит-в-бит равным до конца всех фаз.

## 2. Правила работы

1. **Тест сначала.** Для каждой находки — падающий тест, потом правка. Исключение: чисто текстовая правка локали (там тест на ключи/паритет).
2. **Один вопрос на коммит.** ru и en меняются в одном коммите.
3. **Ветка на фазу:** `fix/review-2026-10-p0`, `…-p1` и т. д. PR-церемонии в соло-репо нет (это решено отдельным коммитом). В `master` — только после «ок» автора.
4. **Стиль коммитов** — по `git log`: одно длинное английское предложение в повелительном наклонении, «что и зачем». Трейлеры — как требует окружение сессии.
5. **Окружение.** Репозиторий разрабатывается на Windows (PowerShell, Git Bash). Перед работой прочитай `Blueprint/11-operational-notes.md`: долгие процессы запускать через `run_in_background`, не `nohup … &`; убивать процессы только узко и по порту; Prisma generate падает с EPERM, пока работает сервер.
6. **Локальный эквивалент CI** (`.github/workflows/ci.yml`), в этом порядке:
   `npm ci` → `npm run prisma:generate` → `npm run build` → `npm run lint` → `npm run format:check` → `npx tsc -p server/tsconfig.build.json --noEmit` → `npx tsc -p client/tsconfig.json --noEmit` → `npx jest --ci` → `npm test --workspace client` → `npm run test:integration --workspace server` → `npm run test:e2e`.
   `npm audit` и `docker compose build` — по возможности, не блокируют фазу.
7. **Решения автора** (раздел 4) — одной пачкой через `AskUserQuestion` в начале. Если автора нет на связи, взять рекомендованный вариант, записать его в отчёт фазы как «принято по умолчанию».
8. **Данные не читать целиком.** `heroes.json`, `pro-matches.json`, `hero-meta.json`, `axis-percentile-distributions.json` — только скриптами, в контекст попадают сводки.

## 6. Риски

- **Контракт `shared/types/battle.ts` ↔ History.** Старые записи читаются «как есть», поэтому любые поля — только аддитивно, удаления — после проверки, что History их не хранит.

- **Соблазн «заодно подкрутить».** Любая находка, которая просится в коэффициент, идёт в раздел «передано в аналитическую сессию» журнала, а не в код.
