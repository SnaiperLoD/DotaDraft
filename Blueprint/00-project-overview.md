# Project Overview

## Project Name

Dota Draft Analyzer MVP

## Purpose

Создать браузерную стратегическую драфт-игру на основе Dota 2.

Пользователь создает команду через процесс Draft, назначает роли героям и получает анализ характеристик своего состава через Evaluation Engine.

Затем пользователь может запустить режим "Схватка" (Battle Mode) — его драфт асинхронно сравнивается с драфтом оппонента, подтянутым из пула (см. `06-battle-engine.md`), и выдаётся результат.

## Main Concept

Это пет-проект с потенциалом вырасти в фановую браузерную игру, а не в аналитический инструмент. Анализ реальных матчей (Evaluation Engine, данные OpenDota) существует не как самоцель, а как способ сделать Battle Mode правдоподобным и интересным — драфты должны ощущаться так, будто они имеют значение, даже если под капотом это статистическая модель, а не полноценная симуляция игры.

Приложение должно оценивать:

- синергию героев;
- игровые стратегии;
- сильные стороны;
- слабые стороны;
- потенциальные контр-угрозы.

Критерий готовности для Battle/Evaluation Engine — "ощущается правдоподобно и увлекательно", а не "статистически защитимо на уровне аналитического продукта". См. `07-development-plan.md` для того, как это влияет на приоритеты по майлстоунам.

## Important

Проект НЕ является:

- полноценным симулятором игровой механики Dota 2 (нет выполнения способностей, нет тайминга, нет исполнения игроком);
- заменой профессионального аналитика;
- коммерческим продуктом в рамках текущего плана.

Проект ЯВЛЯЕТСЯ:

- игрой с разрешённым исходом в Battle Mode (победа/поражение или иной результат), даже если он вероятностный/абстрактный — это не противоречит Accuracy Ceiling Rule (`06-battle-engine.md`): честность в объяснении причин результата не требует отказа от самого результата.

Draft Score и Evaluation Engine остаются информационными (Draft Score Rule, `01-core-rules.md`) — они не сами определяют исход битвы, это делает Battle Engine.

## Monetization

Монетизация в ближайшей перспективе **не планируется** и не является частью текущего roadmap. Проект остаётся некоммерческим pet/fan-проектом; его ближайшие критерии успеха — завершённый core loop, возвращаемость, вовлечённость в серии боёв и качественный пользовательский фидбек.

Предыдущая установка «реклама — единственный предусмотренный источник монетизации» была преждевременным wishful thinking и больше не действует. Не нужно резервировать рекламные слоты, добавлять interstitial/rewarded-видео или оптимизировать продуктовый поток под показы рекламы. Подписки, продажа пользовательских данных и продажа доступа к API/данным также не входят в текущий scope.

Если вопрос монетизации когда-либо вернётся, это должно быть отдельное продуктовое и юридическое решение с повторной проверкой лицензий и правил использования Dota/Valve и сторонних ассетов. До такого решения архитектура и UI не должны предполагать конкретную бизнес-модель.

## MVP Scope

Первая версия:

- работает локально (Draft, Evaluation, History — без регистрации, без Steam API, локальная SQLite);
- использует ограниченную базу профессиональных матчей (см. `07-development-plan.md`, Milestone 3) как часть пула оппонентов Battle Mode;
- Battle Mode подтягивает оппонента асинхронно из общего пула драфтов (про-драфты + драфты, закоммиченные другими игроками) — это единственная часть MVP, которой по природе нужно общее хранилище, а не только локальный SQLite. Явное, осознанное исключение из Data Rule/MVP Rule (`01-core-rules.md`), не распространяется на остальные подсистемы.

## Future Possibilities

В будущем возможно добавление:

- системы брекетов/рейтинга сложности оппонентов в пуле (сильные драфты — выше, про-драфты как потолок сложности, если Evaluation Engine подтверждает их силу);
- персистентного прогресса между сессиями, лидербордов;
- ML моделей;
- расширенной симуляции матчей.
