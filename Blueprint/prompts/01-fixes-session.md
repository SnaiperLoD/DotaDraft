## Контекст

DotaDraft — браузерная драфт-игра по Dota 2: пять раундов по пять кандидатов, ре-ролл, роли вручную, оценка драфта (Evaluation), бой против чужого состава из пула (Battle) с исходом Победа/Поражение и ярусом «Уверенность». Стек: npm workspaces (React/Vite клиент, один процесс NestJS, Prisma → SQLite основная БД и Postgres только для пула соперников, `shared/` типы). Продукт — игра, не аналитика: бой должен ощущаться честным, а экран не должен обещать больше, чем считает математика.

Недавно я заказал независимый разбор автора и системы. Вывод: границы держатся (стена Evaluation ↔ Battle, офлайн-снимки, широкий CI), но есть расхождения там, где игрок читает слово или число, и их не ловят тесты. Исход боя они не меняют. Главный риск вне кода: игра так и не вышла к игрокам.

## Жёсткие границы (и зачем они)

Правила не обсуждаются в этой сессии; они защищают то, что стоило мне недель калибровки.

1. **Не менять математику боя.** Никаких правок значений в `server/data/axis-weights.json`, `server/data/battle-diff-inputs.json`, `server/data/hero-meta.json`; в `server/src/common/calibration-tags.ts` и `server/src/battle/custom-tags.ts` — только структурные изменения без смены значений (T2.1); `battle-shadow.ts` не трогать; `WIN_WEIGHT_BY_TIER`, `REAL_WIN_RATE_CAP`, `HUNT_FLOOR` не трогать. Это Calibration Change Rule. Доказательство соблюдения — golden-снимок из T0.2.
2. **Не запускать рефетч и пересчёт на внешних данных.** Ничего из списка Real-Data Recompute Rule (`fetch-*`, `refetch-*`, `recompute-presumed-positions`, `calibrate-evaluation-values`, `compute-axis-percentiles`, любые OpenDota/Explorer/Liquipedia запросы). `npm run seed` из локальных файлов — можно.
3. **Не вливать shadow, не добавлять скрытые теги, не менять коэффициенты «заодно».** Если находка просится в коэффициент — запиши её в журнал плана как «передано в аналитическую сессию».
4. **Не читать в контекст целиком:** `server/data/heroes.json`, `server/data/pro-matches.json`, `server/data/hero-meta.json`, `server/data/axis-percentile-distributions.json`, `node_modules`, `.stryker-tmp`. Если нужны сведения из них — скриптом, в контекст только сводка.
5. **`master` — только после моего «ок».** Работай в ветках `fix/review-2026-10-pN`.
6. **Не отмечай за меня ручные блокеры запуска** (ссылка, Ko-fi, бэкап, чтение телеметрии, TI Run глазами). Их делаю я.
7. **Не выдумывай механики Dota.** Если для текста нужен факт о героях — бери из данных репозитория и ссылайся на файл.
